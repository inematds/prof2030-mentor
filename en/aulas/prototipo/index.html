Lesson 3 · 20 min

Prototype in one day

With the spec approved, the manager builds the first prototype in a working session with you. They drive the keyboard; you hold the scope, the fictional data, and the checking. By the end of the day there is a tool running on their computer and an honest list of what's missing.

Start the lesson

In this lesson you will

  1. 1Prepare the folder with rules and fictional data
  2. 2Ask only for what's in the spec
  3. 3Check with three cases
  4. 4Save, undo, and note gaps

Goal: lead the session in which the manager builds the prototype with an agent, using fictional data, Git, and a gap list.

  1. 1/6

    Prepare

    A single folder just for the prototype, with AGENTS.md (the manual the agent reads before working), the spec, and a spreadsheet of made-up data. No real customer data comes in today.

  2. 2/6

    Ask

    The manager asks the agent for just one thing, with the expected result. A request that's too big produces changes nobody can check.

  3. 3/6

    Agent builds

    A coding agent in the terminal or the work agent in the chat app. Which one to use depends on what the company already has; this month's list is in lesson 8. The method is the same.

  4. 4/6

    Check

    Open it and test with a common case, an exception, and a missing piece of data. "It opened and looks nice" is not checking.

  5. 5/6

    Save or undo

    Liked it: commit. Didn't like it: git restore. Everything the agent did that the spec didn't tell it to do becomes a line in lacunas.md, which feeds the agent constitution (lesson 4) and the test suite (lesson 5).

  6. 6/6

    One day, several rounds

    Set up once; then ask, build, check, and save as many times as needed. What's left at the end is a prototype that runs and a list of gaps.

The manager does the typing. The mentor asks, points, and checks.

02 · The session in four blocks

One working day, or two half mornings.

1. Before the session

Agree on the equipment: the manager's laptop, the company account on the chosen agent, Git installed. Generate with them a spreadsheet of 20 made-up customers, with fictional names and amounts.

Before building, a rehearsal is worth it: paste the spec into a chat and ask it to play the role of the tool in one case. The questions it asks reveal gaps in the spec.

Rule of the dayNo real customer data. No API key in the browser.

2. Morning

The manager creates the folder, AGENTS.md, and makes the first commit. First request: read-only ("read AGENTS.md and the spec and tell me what you understood").

Second request: the list of open quotes with the rule from the spec. Open it, check it, save it.

Sign that it's going wellBy lunchtime the manager is making requests alone and knows how to go back a version with git restore.

3. Afternoon

Third request: the draft message for each quote, citing only products from the catalog. Fourth: the approve button and the export of what was approved.

Automatic sending, official WhatsApp, and discounts are out: they're not in spec v0.1.

At HorizontePatrícia approved 12 fictional drafts in 10 minutes and edited 3. That's already a number for lesson 7.

4. Wrap-up

Run the three check cases. Everything that surprised you goes into lacunas.md with the date, what happened, and what should have happened.

Set up the next session: write the constitution based on the gaps.

Deliverable of the dayPrototype running + history in Git + lacunas.md with at least three lines.

AGENTS.md for the prototype
# Project: quote follow-up (prototype v0.1)
Owner: Patrícia Lima, sales manager · Mentor: <name> · IT: Rafael

## Rules
- Follow spec.md. If something is not in it, ASK before doing it.
- Use only the data in the dados-ficticios/ folder. Never ask for or use real data.
- Do not put an API key, password or token in any file.
- Do not create automatic message sending, discounts or price changes.
- Simple HTML page that opens in the browser, no server.
- When you finish each task: tell me what changed and how I check it.

## What is here
- spec.md: the one-page spec
- dados-ficticios/orcamentos.csv: 20 made-up quotes
- lacunas.md: what the prototype does not solve yet
Prototype prompt (first build request)
Read AGENTS.md and spec.md before you start.

Task: create index.html, a page that opens in the browser and:
1. loads dados-ficticios/orcamentos.csv;
2. shows only quotes open for 2 business days or more, from active customers;
3. for each one, shows a short draft message (up to 5 lines) that mentions the last
   product purchased and ends with a question;
4. has an "Approve" button per row and an "Export approved" button that downloads a CSV.

Do not: send messages, give discounts, change prices, use an API key.
If a rule is missing to decide, stop and ask me, citing the spec section.
At the end, tell me what you created and how I check it with 3 cases.
Simulation: illustrative example
  1. The page opens in the manager's browser with no server and no key.
  2. Only quotes that the spec's rule says to show appear.
  3. No draft mentions a product outside the catalog or a discount.
  4. git log shows one commit per request.
  • Real data "just to see": once it is inside the chat, it has already left the company.
  • Mentor at the keyboard: the prototype ends up with no owner.
  • Asking for everything at once: changes nobody checks and a scope that blows up.
  • API key in the HTML: this is failure F1 from the lab.

    05 · Practice: the prototype running with the manager

    One real session. If you don't have a manager yet, do it in Patrícia's role.

    E1 · Folder and fictional data

    30 min

    With the manager, create the folder, AGENTS.md, spec.md, and 20 made-up records. Make the first commit.

    Done when: git log shows the first commit and there is no real data in the folder.

    E2 · Prototyping session

    4 h

    Run the session with the script. The manager types every request.

    Done when: the prototype opens on the manager's computer and there is one commit per request.

    E3 · Three cases and gaps

    30 min

    Run a common case, an exception, and a missing piece of data. Note what surprised you.

    Done when: lacunas.md has at least three lines with the date, what happened, and what should have happened.
