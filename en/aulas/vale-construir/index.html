Lesson 2 · 18 min

Is it worth building?

Today you can build almost anything in an afternoon. That is why "it can be done" is no longer a reason. Before the prototype, the mentor runs the idea through a short filter and, if it survives, helps the manager write it on one page: the process, the result, what the tool can do and what it never does.

Start the lesson

In this lesson you will

  1. 1Filter the idea in five questions
  2. 2See the process in six links
  3. 3Decide the seven actions and the data
  4. 4Write the one-page spec

Goal: filter the manager's idea and write the one-page spec, with permissions, owner and the data that stays out.

01 · From wish to one-page spec

The idea goes through four filters. Only what passes becomes a spec. Click each block.

1/6

Real pain

Without pain, nobody changes habits. Ask how many times a week it happens, how long it takes and what is lost when it fails. An answer in adjectives ("it's a lot") is not measured pain yet.

Scroll the page: each step below lights up its part of the diagram.

  1. 1/6

    Real pain

    Without pain, nobody changes habits. Ask how many times a week it happens, how long it takes and what is lost when it fails. An answer in adjectives ("it's a lot") is not measured pain yet.

  2. 2/6

    Shelf life

    If the CRM or the chat the company already pays for will have this as a feature in a few months, building is spending on a short deadline. Sometimes the right answer is "use the feature that already exists".

  3. 3/6

    Recurring use

    A tool used once a month isn't worth the maintenance. The first project of the program must fit into the manager's routine to produce measurable results.

  4. 4/6

    Risk

    The more personal data and the more outbound actions, the earlier IT needs to step in. High risk doesn't kill the idea: it changes the size of the first prototype.

  5. 5/6

    One-page spec

    One page that the manager, the mentor, the company owner and IT read in full. It is what the prototype will follow and what IT will receive.

  6. 6/6

    The whole filter

    Measured pain, long shelf life, recurring use and known risk. What passes all four becomes one page.

Cutting an idea here is a success: it costs a conversation, not a month of maintenance.

02 · How to run the filter and the spec

Click each step.

1. Measure the pain

Ask for five real cases from last week. How many quotes went without a reply? How long does Patrícia spend putting together each message?

These numbers become the baseline for lesson 7. Without them, no one will know later whether the tool helped.

At HorizonteIn one week, 42 open quotes; 17 with no reply in 48 hours. Each follow-up takes about 6 minutes (made-up numbers from the lab).

2. Test the expiration date

Ask: does the CRM or the chat the company already pays for do this, or will it soon? If an 80%-good version shows up inside something everyone already uses, the manager doesn't need their own.

Building something too easy is also a warning sign: if it took half an hour, the vendor can do the same. The value is in the business rules that only Patrícia knows.

Question"If the CRM launches a follow-up button tomorrow, what does your tool still do that it doesn't?"

3. See the process in six links

Every process fits in six links. Input and action are usually delegable. Decision splits in two: the kind that follows a rule (delegable) and the kind that needs judgment (stays with the person).

An exception always goes to a named human. The map shows where the tool comes in and where it stops.

Follow-upInput: quote open for 2 days. Decision (rule): active customer? Action: suggest a message. Verification: Patrícia approves. Exception: customer complained → Patrícia calls. Result: reply logged.

4. Decide the seven actions and the data

For each action, one answer: read, write a draft, change, send, buy (spend margin), delete, and approve. In the first version, reading and drafting are usually "allowed"; changing and sending, "with approval"; buying, deleting, and approving, "not allowed".

For data, one question: does the work come out the same without it? If yes, the data stays out. To suggest a follow-up, the tool doesn't need the CPF.

Rule that settles itEvery row of the matrix has a named owner. Nobody reviews a permission with no owner, and it grows on its own.

03 · Templates: filter and one-page spec

The filter takes five minutes. The spec fits on one page.

Idea filter (5 questions)
IDEA: <name>   MANAGER: <name>   DATE: <mm/dd>

1. Pain: how many times a week? how long each time? what is lost?
   -> <numbers from last week>
2. Shelf life: does the system we already pay for do this, or will it in 3–6 months?
   -> <yes / no / don't know: ask IT>
3. Recurrence: will it be used at least every week?
   -> <yes / no>
4. Risk: does it use personal data? does it send anything outside? does it touch money, price, or orders?
   -> <green / yellow / red>
5. Differentiator: what business rule only we know will the tool follow?
   -> <1 sentence>

DECISION: <go to the spec / use existing feature / archive>  REASON: <1 sentence>
One-page spec — follow-up tool (Horizonte)
# Spec — Quote follow-up · v0.1
Process owner: Patrícia Lima (sales manager) · Mentor: <your name> · IT: Rafael

## 1. Process and result
Every quote open for 2 business days gets a reply to the customer, approved by Patrícia.
Baseline: 17 of 42 quotes with no reply in 48 h (week of <date>).

## 2. Six links
- Input: list of open quotes (export from the sales system)
- Decision by rule: active customer and quote < 15 days old -> suggest follow-up
- Decision by judgment: customer with an open complaint -> Patrícia decides
- Action: message draft (WhatsApp or email), citing only products in the current catalog
- Verification: Patrícia reads, edits, and approves
- Exception: discount request, complaint, missing data -> Patrícia's queue
- Result: reply date logged in the tracking spreadsheet

## 3. Permissions (first version)
| Action | Answer | Owner |
|---|---|---|
| Read quotes and purchase history | allowed | Patrícia |
| Write a message draft | allowed | Patrícia |
| Change quote status | with approval | Patrícia |
| Send message to customer | with approval | Patrícia |
| Give discount / change price | NOT ALLOWED | Carlos (owner) |
| Delete customer or quote | NOT ALLOWED | Rafael (IT) |
| Approve its own message | NOT ALLOWED | — |

## 4. Data that stays out
CPF, bank details, third-party credit limits, entire old conversations.

## 5. Out of scope for v0.1
Automatic sending, integration with official WhatsApp, any discount.

## 6. How we will know it worked
% of quotes with a reply in 48 h · messages approved without edits · zero limits violated.
Simulation: illustrative example
  1. No line of the spec is blank.
  2. At least two actions are in "not allowed".
  3. Every permission row has a named owner.
  4. There is a list of data that stays out.
  5. The baseline has a number and a date.
  • Twenty-page spec: nobody reads it. One page, front and back at most.
  • "Access to the sales system" in a single phrase: it doesn't tell reading, changing, and sending apart.
  • Data "because it might be useful": if the work comes out the same without it, it stays out.

04 · Practice: filter and write the spec

With your manager or with Patrícia.

E1 · Idea filter

20 min

Run the idea you chose in lesson 1 through the five questions, with numbers from last week.

Done when: the filter has all five answers and a decision with a reason.

E2 · Six links

20 min

Rewrite the process as input, decision (rule and judgment), action, verification, exception, and result.

Done when: each link has one line and every exception goes to a named human.

E3 · Spec with permissions

40 min

Fill in the one-page spec with the manager: the seven actions, the owners, and the data that stays out.

Done when: the spec fits on one page, has at least two actions in "not allowed", and one owner per row.
